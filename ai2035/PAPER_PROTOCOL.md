# 第二阶段：前沿研究论文规范

每个项目在第一阶段（`README.md` 分析报告 + `experiment.py` 基础实验）之上，完成一篇面向**全球最前沿**的研究论文。

## 交付物（每个项目目录内）
```
paper.md                 学术论文（中文），本阶段主交付物
frontier_experiment.py   针对所选前沿开放问题的新实验 / 数值验证；输出到 results/frontier.json 与 results/frontier_*.png
CONCLUSIONS.md           结论卡片：≤1 页，供决策者阅读（核心结论、证据等级、置信度、对 2035 的研判）
```

## 前沿证据来源
- `ai2035/frontier/<Qid>.json`：arXiv API 检索的 2025-01 以后论文（id / 标题 / 摘要 / 类别），每题约 100–180 篇。按相关度排序（词汇匹配，不代表质量）——必须阅读摘要后筛选。
- 可用 arXiv API 追加检索（`https://export.arxiv.org/api/query`，间隔 ≥3 秒，`max_results≥1`；遇 5xx 退避重试）。其他网站多数不可达。
- 2025 年之前的奠基性文献沿用第一阶段已核实的引用。
- **禁止凭记忆编造近期文献**：任何 2024 年以后的论文都必须能在 frontier JSON 或 arXiv API 返回结果中找到，并给出 arXiv 编号。

## 论文结构（paper.md）
```
# 标题（具体到所研究的前沿开放问题）

**摘要**（250–400 字：背景、问题、方法、主要定量结果、结论）
**关键词**

## 1 引言          动机；该方向 2025–2026 年的核心争论；本文贡献（3–4 条，具体可检验）
## 2 前沿进展综述   基于 ≥15 篇 2025 年以来的论文（带 arXiv 编号），按技术路线归纳：
                    主要进展 / 共识 / 争议 / 被反驳或未被复现的说法 / 开放问题清单；
                    附“前沿地图”表：路线 | 代表工作 | 关键结论 | 局限
## 3 问题与假设     从开放问题中选 1 个（说明选择理由：重要性 × 可在本环境检验）；
                    形式化定义；预注册假设与否证条件
## 4 理论分析       给出可推导的模型/命题（含推导或证明草图）；理论预测
## 5 实验           设计、对照、≥5 种子、统计检验；实验必须检验第 4 节的理论预测
## 6 结果           表 + 图；逐条对照假设
## 7 讨论           与前沿文献的关系（支持/挑战了哪些论断）；外推边界；局限
## 8 结论           3–5 条结论（[实测]/[文献]/[判断] + 置信度）；对 2035 的研判；后续研究建议
## 参考文献         全部带 arXiv 编号或完整出版信息
```

## 严谨性底线
- 每个数字可追溯到 `results/*.json`；理论与实验不一致时如实报告，并分析原因。
- “解决前沿课题”的含义：在可控的最小模型上给出机理性答案或可检验的判据，并清楚说明它能/不能外推到大规模系统的哪些方面。不得夸大。
- 单个 frontier_experiment.py 单核运行时间 ≤ 4 分钟；仅使用 numpy / scipy / scikit-learn / matplotlib。
