## 5. Radar self-critique

- **Improvement made today: re-observation by API.**
  - `recheck` leaves out apps already read today. Without that, 594 entries
    were listed, almost all repos the API search had just read.
  - `collect` re-reads the remaining repos through the search endpoint as
    collector `api:github-repos`, with exact counts instead of "58.7k".
  - Per-repo REST reads (`/repos/owner/name`) are refused by the
    environment's proxy (403). The search endpoint, which the topic
    collector already used, answers, so the re-reads go through it.
  - No page-read recheck subagent was needed today.
- **Follow-on fix, same cause.** The watch list's automatic search terms had
  picked up generic words: "engine", "without", "working", "unified" and
  "ad-free". Once the API answered, each pulled in up to 150 repos (Godot,
  Redis, Elasticsearch). Those words are now generic: never mined, and
  pruned from the list. The 168 repos already registered stay, because
  observations are append-only.
