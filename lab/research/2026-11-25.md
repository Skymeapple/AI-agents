## Improvement shipped: pthscan 0.2.0

Python's `site` module imports `sitecustomize.py` and `usercustomize.py` at every interpreter start. That's the same blast radius as `.pth` hooks, and this is documented Python behaviour, so no web sources were needed. 0.1.0 ignored them.

* Checked at the top level of each site dir **and** the interpreter's stdlib dir (where Debian/Ubuntu put `sitecustomize.py`, via a symlink into `/etc/python3.X/`).
* Empty files and Debian/Ubuntu's apport crash handler are recognised by normalized content. Strong stealer indicators (base64, network, credential stores, encoded blobs) or 3+ indicators make it critical; anything else is a warning to review.
* Copies inside package subdirectories (ddtrace, OpenTelemetry auto-instrumentation) are ignored: they only run when explicitly put on `PYTHONPATH`.
